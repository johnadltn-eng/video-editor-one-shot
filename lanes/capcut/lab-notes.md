# CapCut lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is CapCut mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`).

- **CapCut lane = `lanes/capcut/capcut-bridge.py`, built + validated 2026-07-27** (CapCut 8.9.0, `com.lemon.lvoverseas`). CapCut has NO API, so the bridge runs two lanes. **File lane:** drafts are plaintext JSON under `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/`; `replay <job>` writes a whole draft straight from `transcript/cuts.json` — one timeline segment per cut, source times in **microseconds**, `target_timerange` butt-joined so the cut lands where the EDL says (verified segment-by-segment against the intro EDL: 10/10 exact, zero drift). A draft needs three files in sync — `draft_info.json` (timeline + a `materials.videos` entry + the six per-segment helper materials CapCut itself writes: speed/placeholder/canvas/channel-map/color/vocal-separation) + `draft_meta_info.json` + an entry inserted into the shared `root_meta_info.json` registry — and **CapCut must be QUIT while writing** (it rewrites that registry on exit and will clobber the new row). **The sandbox is the gotcha:** CapCut ships `com.apple.security.app-sandbox` with only `assets.movies.read-write`, so ANY path outside `~/Movies` opens as a red "File not accessible" timeline behind a Link media dialog — the bridge hardlinks the raw into `<draft>/Resources/` (same APFS volume, zero bytes copied) and points the material there. **Live lane:** the QML UI exposes ByteDance's internal automation IDs through the macOS AX tree, so `open`/`clips`/`playhead`/`play`/`click`/`key` find elements by name and click their centers with synthesized CGEvents — a real locate → act → verify loop (validated: playhead read back advancing during playback). Gotchas: the transport button's id flips `PlayerPlayBtn` ↔ `PlayerPauseBtn` with state; the window can reposition across displays after launch, so re-find geometry right before clicking, never cache it; dialogs (Link media) expose only the container, so buttons need offset clicks; `osascript` quit returns a harmless `-128`. AX ids are internal test hooks, NOT a contract — re-verify with `dump` after any CapCut update. Premiere is a separate lane; this one is CapCut. **Alpha graphics + overlay tracks validated 2026-07-27 (drop-test, g1txt.mov):** HyperFrames ProRes 4444 movs composite with true transparency on a second video track — overlay track = `flag: 2` with segment `render_index`/`track_render_index` = 1 (the 0528 recipe); text tracks are `flag: 1` + `materials.texts` (schema in 0528). **`Timelines/` cache gotcha, cost the first drop-test:** on first open CapCut imports `draft_info.json` and builds native state in `<draft>/Timelines/`; from then on Timelines wins and post-hoc JSON edits are silently IGNORED. To file-lane-edit an existing draft: quit the app, rewrite the JSON, and DELETE `Timelines/` + `draft_info.json.bak` to force a re-import (fresh `replay` drafts are unaffected, no cache exists yet). **Re-adding a RE-RENDERED overlay serves the OLD file, silently (2026-07-30, title cards):** `add-overlay` copies the mov into `<draft>/Resources/` and skips the copy when that filename already exists, so a v2 render at the same path never reaches CapCut — and every check passes (segment times, material paths, `clips`, `state` all read correct; only the Resources copy's hash/inode differ). It also strands the segment on the OLD media duration, so a longer v2 leaves the segment reading past the end of its file. Fix: `rm <draft>/Resources/<name>.mov` first (breaks the hardlink to the stale inode), re-copy, patch `materials.videos[].duration` + any `source_timerange`/`target_timerange` that now overruns, then wipe `Timelines/`. Use `--force`, or version the filename. **Verify a re-render landed by hashing the Resources copy against the render — never by re-reading the timeline.** **Once you have hand-edited a draft in the app, additive-edit the CURRENT draft_info.json** (your edits are saved into it on quit) — never regenerate from the EDL; a rebuild clobbered a hand-extended segment on 2026-07-27. Import also re-quantizes cuts to the timeline's 30fps grid (≤17 ms shift per cut vs the 23.976-snapped EDL — eats into the refine pass's 40 ms onset margin; acceptable for this lane, don't fight it). **Can we build a real CapCut API? Researched 2026-07-27, answer is no — but the live lane is better than the restart story suggests.** Probed and ruled out: no public desktop automation API (CapCut's "Open Platform" is editor plugins only); `--remote-debugging-port=9222` DOES work and serves full CDP (CEF 121, and the page exposes a `cefCallNativeFunction` JS→native bridge), but the editor UI is native Qt/QML — CEF hosts only auxiliary webviews (blank/about:blank with the editor open), so CDP reaches no timeline state; injection is technically unblocked (`disable-library-validation` + `allow-dyld-environment-variables` + `allow-jit`) so hooking `libVECreator.dylib` (655 MB, stripped) could expose a true API, but that's a reverse-engineering project that breaks on every auto-update — not for a pipeline you depend on. **What IS live, validated by read-back with zero restart: select a clip → `del` → 10→9 clips → `undo` → 10.** Same select-then-toolbar pattern extends to `cutoff` (split at playhead), `cutLeft`/`cutRight`, markers, copy/paste. So: **file lane = bulk/structural builds (a fresh `replay` never needs a restart — the cache only exists after first open), live AX lane = interactive edits, no restart.** **Full export validated end-to-end 2026-07-27** (`export` command): drives CapCut's own export dialog and verifies the file that lands (raw EDL → alpha overlay + programmatic text → 1080p HEVC mp4 in ~/Downloads, both graphics confirmed baked into the render by frame-grab). Three export gotchas cost real time: (1) the post-export "share to TikTok/YouTube" screen is MODAL and blocks the next export — `send_key("escape")` before AND after; NEVER click through it (it publishes). (2) The export dialog is a centered QML overlay with NO AX internals — its Export button and the sync-to-cloud checkbox are reached by CENTER-relative offset clicks (`EXPORT_BTN_OFFSET`), same as Link media; the "Sync exported videos to space" toggle uploads to CapCut cloud, is sticky-off, and must NOT be blind-clicked. (3) **A `source_timerange: null` on any segment WEDGES the encoder mid-render (froze at exactly the text seg's 30% mark, twice).** CapCut writes null there for text segments internally, and it survives a file-lane rewrite into the re-imported draft — `edit_draft` now backfills every null source range from the target duration before writing. A wedged export needs `kill -9` (the modal blocks a graceful quit) + delete `Timelines/` before relaunch. **Export drivable end-to-end, validated 2026-07-27:** `capcut-bridge.py export` escapes any lingering modal, clicks the title-bar Export + the dialog's Export (center-offset clicks — the export dialog, like Link media, exposes NO AX internals), then polls `~/Downloads` for the new mp4 and ffprobes it (proven twice: an 86.7 MB and a roughly 76 MB export, both verified; the tail of this sentence was truncated in an early commit, exact second figure lost). **CapCut composites ProRes 4444 alpha as PREMULTIPLIED; hyperframes renders STRAIGHT:** solid glyphs look fine (which is why the g1txt validation missed it), but semi-transparent pixels (motion blur, glows, soft shadows, fades) blow out toward white. Premultiply every CapCut-bound alpha mov first (`format=rgba64le,premultiply=inplace=1` → re-encode ProRes 4444; the recipe is the ffmpeg line above). Premiere assumes STRAIGHT: never premultiply a Premiere-bound render.
- **The converter is this lane's own script: `bash lanes/capcut/premultiply.sh <in.mov> [out.mov]`** (default output `<in>-premult.mov` beside the input; it prints the path it wrote). The preset builders render STRAIGHT alpha and know nothing about CapCut — the conversion belongs here, run it before `add-overlay`.
- **CapCut cutout + layer order, validated 2026-07-27** (text-behind-subject on the your-job intro). **Background removal IS drivable live** and it's CapCut's own AI matte (Pro): select the clip → `click "VESettingPanelSubTabControl:Remove BG"` → offset-click the Auto removal checkbox at the LEFT edge of `automationaiMattingGroup` (the row exposes no AX child, same as the export dialog). It writes `matting.flag: 3` + a mask cache in `<draft>/matting/<hash>/` keyed on the MEDIA, so a second clip off the same raw recomputes fast; flag 0 = off, 1 = requested-not-applied, 3 = live. **Z-order is TRACK stacking, not segment `render_index`** — `render_index` only orders within a track, `track_render_index` + tracks-array order composite, and a text track can NEVER go below a video layer (out-of-band values like ri 15000 don't move it, they just look like they worked). Type that must sit *behind* a subject gets baked to an alpha ProRes overlay, not a CapCut text track. The stack is main → black clip (its `clip.alpha` IS the background-darkness knob) → title mov → muted duplicate of the same footage with the matte on (`add-overlay --src <in-point> --mute --force`; unmuted it doubles the voice). **The QA trap that ate an hour:** the cutout layer is the same footage as the main track, so until the matte lands it covers the frame and every layer under it reads as "not rendering" — verify `matting.flag == 3` in the JSON or `delete` the top clip before debugging anything below it. **Motion keyframes are fully file-lane writable (same day):** `common_keyframes` on the segment, one entry per `property_type` (`KFTypeScaleX/Y`, `KFTypePositionX/Y`, `KFTypeRotation`, `KFTypeAlpha`), each a `keyframe_list` of `{time_offset µs in the SOURCE time domain (= `source_timerange.start` + offset from the segment start, NOT segment-relative), values: [v], curveType}` — so zooms/pushes/moves have the same range as Premiere's Effect Controls, and land more exactly (values written, not typed into a UI that rejects synthetic input). `keyframe` / `clear-keyframes` commands. Only `curveType: "Line"` is verified; ease-curve names are unprobed — stack extra keyframes instead of guessing. Schema was learned by making ONE keyframe by hand in the app and reading the JSON back — reuse that trick for anything else the inspector does. Keyframing the cutout layer alone gives real parallax (subject pushes in, background holds). **Coach-marks swallow clicks (2026-07-27, cost half an hour):** CapCut pops yellow onboarding tooltips that overlay the UI and are INVISIBLE to the AX tree — `dump` looks clean, every live command reports success, and nothing happens in that screen region. One parked over the left end of the ruler ate all clicks near t=0, so `seek`'s two-point `calibrate` fitted garbage off the single point that landed and the playhead ended up 40s from target. It also produced a false 'the importer flattens keyframes' conclusion — the start-frame grab was never at the start. **Rule: when a live action reports success but state didn't change, `shot` the window and look for a yellow bubble** (dismiss via offset click on its OK); take a `shot` at the top of any live session. **The keyframe time domain cost most of an afternoon and fails SILENTLY (2026-07-27):** segment-relative offsets land outside a real cut's source window and CapCut collapses the whole animation to ONE static value instead of erroring — the clip reads as zoomed but never moves. It also hides during testing: the first probe used a clip whose source in-point was 0, where the two domains are identical. **Verify keyframes by parking the playhead BETWEEN two of them and reading the inspector** (100 → 112 → 122 = interpolating; last-keyframe value = flattened) — program-monitor frames are NOT proof, a talking subject leaning toward camera reads exactly like a push-in and fooled me into calling it validated twice. Three live-lane traps found alongside it: the ruler has a ~90px DEAD STRIP at its left edge that eats clicks (so seek lands where it can and closes the gap with arrow steps); frame steps must be PACED (195 sent back-to-back, 28 applied); and synthesized input only lands when CapCut is frontmost — un-fronted, the FIRST click is consumed activating the window, which made `calibrate`'s probe A read a stale playhead and fit garbage.
- **CapCut earrape audio on a MOV that plays fine in QuickTime/Premiere (2026-07-28, test-footage):** the clip was a QuickTime Player movie recording at Maximum quality, which writes ProRes video + 32-bit big-endian PCM audio with a header variant that ffmpeg-lineage parsers (ffprobe reports `pcm_s24be`; CapCut's importer makes the same read) misframe as 24-bit, decoding as full-scale static. CoreMedia (QuickTime, Premiere) reads it correctly, so the source is NOT broken. Diagnose in seconds: per-second RMS dead-flat around −8 dB = misframed PCM, not hot audio (real speech always has dynamics). Fix at intake: `afconvert -f WAVE -d LEI24@48000 <raw.mov> audio.wav` (CoreAudio decodes it right), then remux `ffmpeg -i raw -i audio.wav -map 0:v -map 1:a -c:v copy -c:a pcm_s24le`. Second lesson, cost the draft: never swap media files under an existing draft; the bridge's `quit` races CapCut's async shutdown save, which zeroed `draft_info.json`. With no hand edits, just delete the draft + registry row and `replay` fresh against the fixed media.
