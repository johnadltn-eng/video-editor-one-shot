# Premiere lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is Premiere mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`).

- **Premiere-path jobs NEVER render the flat cut (2026-07-22, learned twice on a real job).** When the finish surface is Premiere, run `RENDER=0 splice.sh <job>`: refine + frame-snap + persist EDL + corrected canonical transcript in ~8s, no ffmpeg encode ever. Then `premiere-bridge.mjs replay` immediately. Nothing on the Premiere path consumes the flat MP4 (a 4K one cost 20+ min and the whole handoff sat behind it); audio-qa is render-dependent and skipped. **Do NOT touch audio during a rough-cut handoff (2026-07-30):** no Amplify, no clip gain, no level-matching between sections, even when one section reads several dB quiet. Measuring levels as information is fine; acting on them is not. (This supersedes the earlier scale-the-A1-Gain instruction that lived here.) The metric is time-to-timeline: transcription is the only slow step allowed. **The audio polish is pipeline step 3, run immediately after the replay lands (2026-08-28 — supersedes the same-day "after picture lock" placement):** apply the house chain ON the Premiere timeline as clip audio effects — `uv run lanes/premiere/audio-polish.py projects/<job> --apply` (2026-09-03; the gain is MEASURED by `workflows/voice-gain.py`, kept speech → −17 LUFS pre-limiter, so +10/+8 are no longer rules; the ADD path was validated on a scratch sequence the same day), which is Amplify (Left/Right `v=(dB+96)/144`) + Hard Limiter Maximum Amplitude at −6 dBFS (`v=(dB+100)/100` → 0.940) on every A1 clip via QE `addAudioEffect` + DOM property writes, readback-verified (validated 2026-08-28 on your-job, 31/31 and 35/35 clips). ONE pass over the whole timeline, never per-section during the cut; the effects stay hand-tweakable in Effect Controls, and your later hand-trims keep them — but **a timeline rebuild (clear + re-replay) discards clip effects, so re-apply the pass after any re-replay before saving.** Resolve keeps its own route (ffmpeg-on-source + ReplaceClip, `lanes/resolve/resolve-audio-polish/` — its API has no audio-FX surface).

Recipe + engine arg quirks: the skill's "Graphics in Premiere" section. **The bridge `zoom` command takes `at` (a SEQUENCE timestamp) or `offset` (frames) to start a ramp mid-clip (2026-08-31)** — that is how an emphasis push-in is baked, vs the default in-point start for the opening zoom-out. With a start past the in point it clears only from the ramp start onward, so a clip holding BOTH the opening zoom-out and a push-in keeps the opening move; it refuses and writes nothing if the ramp would begin before the clip or overrun its end. Keyframe source-time domain + read-back-after-write discipline apply regardless of engine.
- **The step-4 grade stack on this lane (the law and the why: `CLAUDE.md` § Lab Notes; other lanes: [`LANES.md`](../../LANES.md) § step 4).** One adjustment layer spanning the timeline, on the track directly above the footage and directly below the graphics: **V1 footage → V2 grade → V3 graphics → V4 accents.** A Premiere adjustment layer affects every track BELOW it, so that stack grades the footage and nothing else. **Clip transforms are a non-issue:** zooms and push-ins are clip-level Motion/Transform on V1 and are applied before the adjustment layer sees the composite, so the grade lands on the already-transformed image and re-baking a move never touches it. **Consequences to carry:** graphics placement moves V2 → **V3** on this map (the bridge takes the track index as an argument, so no code changes, only the placement call); generated b-roll dropped above the grade stays ungraded, which is usually right for a Higgsfield clip but is a choice, not an accident; and the OPPOSITE stack (V4 adjustment layers over everything, per-section Lumetri) is the your-job vox-era architecture, which as of 2026-08-31 lives ONLY inside its own preset at `presets/youtube/vox-collage/premiere-lane.md` (the vox-only scoping rule). It used to sit in `workflows/premiere-graphics.md`, where a scope banner was the only thing stopping a fresh session from stacking the grade on top; the lane-agnostic half of that doc (keyframe laws, clip lifecycle, b-roll placement) moved into the `premiere-pro` skill, so no shared doc teaches the wrong stack any more. **BUILT AND STANDING ON `your-job` 2026-09-01, and the LOOK is now locked too: [`assets/luts/rec709/Autumn-Rec709.cube`](../../assets/luts/rec709/Autumn-Rec709.cube)** (the house Rec709 LUT, chosen over London), at Lumetri → Creative → Look; there is no correction step, and if a clip ever needs a manual one it goes in Basic Correction of the SAME instance, because a Look renders after the dials. **Retrofitting the grade track onto a timeline that already has graphics is ONE call, not a re-lay:** QE `addTracks(1, 1, 0, 0, 0, 0, 0)` INSERTS a video track at index 1, so everything on the old V2 shifts up to V3 with every effect, keyframe and trim intact and the new empty track becomes the grade track (verified: 25 graphics clips moved, zero touched). Never move graphics by re-`overwriteClip`-ing them, that rebuilds from the project item and drops their clip effects. **THE LAYER IS ONE COMMAND, AND IT IS SIZED TO THE SEQUENCE (2026-09-02): `node lanes/premiere/premiere-bridge.mjs grade-layer`** with the job's sequence active, it provisions the V1/V2/V3/V4 tracks, mints an adjustment layer at the frame size it READS off the sequence (never typed), imports it, spans it across V1 on V2, names the clip `GRADE`, adds Lumetri, flags any muted track, and saves; it refuses if that track already has a `GRADE` clip and reuses a same-size layer already in the project, so re-running is safe. Verified pixel-identical to the hand-built version (max channel delta 0). Scripting still cannot CONSTRUCT an adjustment layer, so a donor import is the route and the donor is a fixed 3840×2160, which is why the size is read rather than assumed (a 16:9 layer on a VERTICAL sequence can be scaled to fit and leave the top and bottom ungraded, silently). Mechanics, the `mint-adjustment-layer.py` internals and the `--which N` multi-Lumetri trap: [`lanes/premiere/premiere-grading.md`](../../lanes/premiere/premiere-grading.md) and the `premiere-pro` skill Notes. **Which lanes have a recipe for this step at all: [`LANES.md`](../../LANES.md).** Target and numbers (the WHAT): [`presets/youtube/default/README.md`](../../presets/youtube/default/README.md) § Grade.
- **`.lookparams` pid 4 MUST be the explicit empty sentinel, never self-closing (2026-09-02, your-job, the first fresh job through the locked grade).** The 16:31 re-mint of `Autumn-Rec709.lookparams` captured the Input-LUT path param (pid 4) as `<StartKeyframeValue …/>`; every earlier capture carried `>/v4=</StartKeyframeValue>`, and Premiere refuses a LUT'd Lumetri without it ("The project appears to be damaged"). Found by bisect: five variants built offline from the pre-LUT backup, one open each; the pid-4 variant was the only one that opened. The params file is fixed, and the class is closed at the tool: **`grade-lut.py selfcheck`** proves every shipped params file OFFLINE (element shapes, the BinaryHash length word = payload + 12, the embedded cube's float data against the `.cube` beside it, the dials, the 128-byte component struct, sha256 drift against `assets/luts/README.md` § Checksums), `capture` runs it on the file it just wrote, `apply` runs it before touching a `.prproj` and refuses a failing file, and both rewrite a self-closing pid 4 as the sentinel; the packaging guard calls it too. Nine damaged fixtures all fail it, a recapture from the damaged donor now comes out byte-equal to the fixed file. Same session, the locked-screen lesson: **with the Mac password-locked the headless bridge, the replay, the audio polish, `grade-layer`, `frame` grabs and the whole graphics pass all work, but Premiere's own UI does not**, AX sees no windows, menu presses and Cmd+Q/Cmd+O posted to the process are ignored, `open -a <file>` is ignored by a running Premiere, and `premiere-up.sh` cannot relaunch a project. What DOES land: a bare Return key posted straight to Premiere's pid (`CGEvent.postToPid`, scratch tool `keypid`) dismisses a native alert, and an AppleEvent `open POSIX file` opens a project once no modal is up. Diagnose a stuck Premiere with `sample <pid>` (a `UI_MessageBox::RunModal` frame = a modal you cannot see); window buffers grab blank under the lock, so never trust a `window-grab` there. Both primitives are now `lanes/premiere/premiere-dismiss.sh` (`--check` = exit 2 while a modal is up; bare = post Return to the pid until it is gone; it finds the pid through `lanes/premiere/premiere-pid.sh`, THE one "is Premiere running" check: the process is year-suffixed, `Adobe Premiere Pro 2026`, so a hand-typed `pgrep -x "Adobe Premiere Pro"` says "not running" with the app on screen, and a `pgrep -f` on the path picks AdobeIPCBroker's lower pid; `ping` is what answers "drivable"), and the hard gate is written down: after ANY refused open, nothing else opens until it reports zero (five queued opens wedged Premiere past any quit). `grade-lut.py apply` now writes into a COPY that is cold-opened and swapped only after the frame delta proves it.
- **LUMETRI'S LUT: NOT reachable through the scripting API, but SOLVED by writing the project file, `lanes/premiere/grade-lut.py` (2026-09-01, Premiere 26.3.2). The whole mechanism, every measurement and every trap now lives in [`lanes/premiere/premiere-grading.md`](../../lanes/premiere/premiere-grading.md), read it before any grading work on this lane.** The locks worth carrying at this level: **the MCP's own `apply_lut` tool is a MEASURED no-op that reports success, and it is UNSAFE on a grade layer** (it writes into `components[numItems-1]`, so on a clip that already has a Lumetri, which every GRADE layer does, it resets the existing instance); all six LUT-looking ES params accept writes and render nothing; **writing the `Blob` param through ES POISONS the instance** so it renders nothing at all, not even Exposure; `BinaryHash` is validated and a wrong one is discarded SILENTLY, which is why the params are captured from a hand-applied project and replayed verbatim rather than synthesized; the payload is FIVE pieces, four params plus the component's own `PremiereFilterPrivateData` struct, and a params-only write is what produced five "project appears to be damaged" files in one afternoon; ObjectIDs are NOT unique in a `.prproj` so every lookup disambiguates by `ParameterID`; **always copy the `.prproj` before running the tool** (it corrupted a live job project once, recovered only from a backup); the LUT goes in **Creative > Look**, never Basic > Input LUT; the captured params EMBED the cube and are portable across machines, but Premiere re-resolves the LUT on its next save and drops the embed, which is why captures are taken from `/Users/Shared/`; and the params are **VERSION-BOUND** to the Premiere they were minted on, with no check anywhere. ☠️ **Three different failures all present as "the grade does nothing", a muted track, a poisoned effect, a discarded payload, and none is visible in a readback.** Never trust a readback; verify only from a program render with the layer toggled, and re-run the Exposure +2 control (must move mean RGB ~46 points) on a track you have confirmed is unmuted before believing any negative result.
- **YouTube export = CBR, not VBR (2026-08-02, your-job delivery).** Premiere's H.264 exporter on Apple Silicon runs through VideoToolbox, whose VBR treats the "target bitrate" as a **ceiling**: a 27-min 4K sequence set to VBR 50/65 landed at **17.6 Mbps average** (dense intro saturated the cap, screen-recording bulk coasted at 11). Set `ADBEVideoBitrateEncoding` to **0 (CBR)** in the `.epr` and it hits 50.0 Mbps exactly. Measured on a 15s screen-recording section against a ProRes 422 HQ reference of the same range (`ffmpeg -lavfi libvmaf`): VBR 50/65 = 96.63, VBR 65/80 = 96.77, **CBR 50 = 97.44**, CBR 65 = 97.44 (identical to 6 dp), ffmpeg x264 CRF 14 software = 97.21. **50 Mbps IS the ceiling** — more bits change nothing and software encoding scores lower, so the remaining gap is the 4:2:0 8-bit conversion H.264 delivery requires, not the encoder. Recipe: patch each `<ExporterParam>` block of the `.epr` by regex within the block (the identifier tag precedes ParamValue in the H.264 exporter but follows it in others, so never zip the two tag lists positionally); poll `lsof` on the output file for completion (the bridge call always times out at 45s and ffprobe reads a bogus duration mid-write). No preset ships: author the `.epr` fresh by exporting an H.264 preset from Premiere, then patch it per the recipe above. Keyframe distance is not settable this way (hardware encoder writes 2s GOPs regardless; YouTube asks for half the frame rate, harmless).

Never Premiere's save-dialog default — that's the rotating Auto-Save folder, which Premiere prunes on its own schedule (your-job's two .prproj files were rescued from it). **Relocating a .prproj leaves its history behind (2026-07-29):** Auto-Save follows the project file, so pre-move autosaves stay in the OLD job's `premiere/Adobe Premiere Pro Auto-Save/` — one job's drafts hiding in another's folder. After any relocation, sweep the old folder (`find projects/<old-job> -iname "*<job>*"`) into `<job>/premiere/archive/`, never into the live Auto-Save folder (Premiere prunes that). - **Drive the editor in the BACKGROUND; never front an app to screenshot it (2026-07-29).** You work in other apps while Claude drives Premiere, so `open -a` to grab a frame interrupts you. `./workflows/window-grab.sh <App> <out.png>` captures a window's own buffer via `screencapture -l<windowID>` — occluded and other-Space windows grab fine (`screencapture -D <display>` only sees what's on top). Window IDs come from `CGWindowListCopyWindowInfo` through an inline Swift program (system python3 has no Quartz; don't pip-install pyobjc). `--list` enumerates; the index arg reaches dialogs/panels. Minimized windows have no buffer and grab blank. Most verification needs no pixels at all — read state back with `execute_extendscript`; reserve grabs for what has no read API, like timeline clip COLOR LABELS. **Those labels are inherited from the PROJECT ITEM at insert time and are not scriptable per clip (2026-07-29):** neither DOM `TrackItem` nor QE exposes a color-label getter/setter, so recoloring the item after a replay leaves the already-laid clips on their old color. To color a section, `projectItem.setColorLabel(n)` FIRST, then lay the clips; to recolor after the fact, remove and re-lay them (`app.enableQE()` → `getVideoTrackAt(0).getItemAt(i).remove(false,false)`, iterating backwards, and repeat on the audio track — video and audio remove independently). Guard the loop on `it.name` so it can only delete the section you meant. Verify the color by sampling pixels out of a `window-grab.sh` capture, and force a repaint first (nudge the playhead) — a backgrounded Premiere serves a STALE timeline buffer that shows the old color even after the change registered. Launch + bridge autostart is `./lanes/premiere/premiere-up.sh [project.prproj]` (CEP panel patched with `<StartOn>` + an autostart shim in `bridge-cep.js`, mirrored into `vendor/premiere-mcp/cep-plugin/`; original backed up outside the extensions scan path). **That patch is applied by `lanes/premiere/premiere-templates/apply-autostart-patch.py`, not by hand and not by `patch` (2026-09-02)** — it edits by CONTENT, so it is idempotent, needs nothing but python3 (Git Bash has no `patch` binary), and survives upstream line drift; verified byte-identical to the reference panel. **Re-run it after any engine re-clone, version bump, or cep-plugin re-copy**, or the panel silently reverts to click-to-start. `setup-premiere.sh` now calls it on a client's first run — before that fix a client got a PRISTINE clone of the plugin and had to click Start Bridge every session, which quietly made the whole 'autonomous grade' story false on any machine but the one it was developed on. **`--restart` never force-kills:** Premiere treats any non-graceful exit as a CRASH; the crash dialog blocks the CEP panel on next launch and post-kill timeline state comes back subtly wrong. Save via the bridge, graceful quit, wait; if it will not quit, STOP and tell you (a wedged Premiere is yours to quit by hand).
- **OBS screen recordings need a remux before Premiere will import them (2026-07-29, your-job).** OBS writes an `.mkv` + `.mp4` twin, and the mp4 carries **two identical AAC audio tracks**. Premiere silently refuses the whole file: `importFiles` returns `true`, `qe.project.importFailures` is empty, and NOTHING lands in the panel — no error anywhere. Isolate it by test-importing a known-good raw (a camera `.MP4`); if that lands, the file is the problem, not the bridge. Fix is lossless and keeps timing exact: `ffmpeg -i raw.mp4 -map 0:v:0 -map 0:a:0 -c copy -movflags +faststart out.mp4` (HEVC Main/hvc1 imports fine — the codec is not the issue, the track count is). Null-test the two tracks first (`amerge` + `pan=c0=c0-c2|c1=c1-c3` → volumedetect; −91 dB flat = bit-identical, nothing lost). Duration is unchanged, so an EDL cut before the remux still applies. **Clip deletion IS scriptable** (supersedes "have you delete panel items by hand"): DOM `deleteBin()` and `deleteItem()` no-op on a clip, but `item.moveBin(bin)` into a fresh `rootItem.createBin()` then `bin.deleteBin()` removes clip + bin — verified removing two stray imports.
- **yt-dlp downloads headed into Premiere must be H.264.** The default "best video" grabs YouTube's AV1 stream (f401), which Premiere can't import ("unsupported video compression type av01"). Force `-f "bv*[vcodec^=avc1]+ba[ext=m4a]/b[vcodec^=avc1]"` (caps at 1080p since YouTube only serves avc1 up to 1080p; fine for edit sources). (Moved from global CLAUDE.md 2026-09-02.)

- **Step-6 SFX placement validated 2026-09-03 (your-job, 120/120 rows, first run ever).** `lanes/premiere/place-sfx.py` is the placer; the plan is universal (`workflows/sfx-plan.py`, WHAT in `presets/youtube/default/sfx.md`). Three things learned on the run: (1) QE `addTracks(0, 0, 1, 1, audioTracks.numTracks, 0, 0)` appends ONE stereo audio track (arg order video-count, video-index, audio-count, audio-type, audio-index, submix-count, submix-index), verified by readback 3 → 4; (2) an audio-only project item takes `setInPoint(t, 4)` / `overwriteClip` exactly like the replay's A/V clips, and clearing the in/out afterwards is required or the next slice inherits them; (3) **the bridge CLI logs to STDOUT, and the "Executing tool" line prints the whole args object MULTI-LINE when the script is long**, so a parser that drops lines starting with `[` still sees the log's `script: '...'` and `}` lines and reads non-JSON. Parse the LAST top-level JSON value (scan backwards for an unindented `{`/`[` line) as `place-sfx.py` does; `place-graphics.py` gets away with `json.loads(stdout)` only because its scripts happen to keep the log on one line. The clip Volume > Level encoding is `v = 10^((dB − 15) / 20)` (0 dB = 0.17783), confirmed by writing eleven distinct values and reading them back.
