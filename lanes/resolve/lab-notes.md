# Resolve lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is Resolve mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`).

- **Resolve auto-conforms mismatched resolution — do NOT hand-scale 1080p assets on a 4K timeline (2026-08-05).** The project setting `timelineInputResMismatchBehavior` defaults to **`scaleToFit`**, so a 1920×1080 clip (title card, alpha overlay, older footage) already fills a 3840×2160 frame on drop. Applying the Premiere habit — Motion Scale 200, which that lane genuinely needs — **doubles it to 400% and crops the middle out**, and it looks plausible enough to ship: the title card lost its first and last letters and the talking head just read as a tighter shot. Set `ZoomX`/`ZoomY` to **1.0** and let Resolve conform. Check the setting before scaling anything, and verify with a real render — the crop is invisible in a clip-level readback (every item reported the zoom it was told to hold). **Mixed-fps conform is the good news:** a 29.97 clip on a 30.000 timeline conforms **frame-for-frame** (1609 source frames occupy 1609 timeline frames), so frame-indexed graphics keep their exact positions, and overlays rendered at the same source rate take the identical conform and stay in sync — no re-render needed to move a finished 29.97 job onto a 30 fps master.
- **Resolve graphics lane validated 2026-08-05** (`your-job` intro, 9 graphics on V2). HyperFrames alpha ProRes 4444 renders drop onto a Resolve timeline with **zero alpha config: Resolve auto-detects `Alpha mode: Straight`**, which is exactly what hyperframes writes — **never premultiply a Resolve-bound render** (that is the CapCut lane's fix and would blow out every soft pixel). Placement is `AppendToTimeline` with `clipInfo` `{mediaPoolItem, startFrame:0, endFrame:<frame count>, recordFrame:108000+start, trackIndex:2, mediaType:1}` — `endFrame` is **EXCLUSIVE** here too, `recordFrame` is ABSOLUTE. Script it (`hf-graphics/place.py`, idempotent, readback-verified); Resolve's embedded Python opens files as **ASCII**, so `io.open(..., encoding='utf-8')` or an em dash in the timeline name kills it. **`TimelineItem` has NO keyframe API** (only static `SetProperty` + the Fusion methods), so an animated footage move is a Fusion comp on the clip: `AddFusionComp` → `add_tool Transform` → connect MediaIn→Transform→MediaOut → `add_keyframe` on `Size`; verified interpolating (1.0→1.07 reads 1.035 mid-clip). **`timeline_markers get_thumbnail_image` returns the CURRENT CLIP's frame, not the program composite** — over a graphics track it shows the overlay on black and proves nothing; verify compositing with a real render (`SetCurrentRenderFormatAndCodec` + `AddRenderJob` + `StartRendering`, 54s of 1080p in ~2 min).
- **Resolve grading = a COLOR GROUP + one DCTL, validated 2026-08-06** (`your-job` intro: 9 clips, one shader, verified by render). Full playbook: [`lanes/resolve/resolve-grading/`](../../lanes/resolve/resolve-grading/README.md) — **required reading before any grading work**, with a working reference shader + numpy previewer. **A color group IS Resolve's adjustment layer and it's fully scriptable:** `project.AddColorGroup(name)` → `item.AssignToColorGroup(grp)` → `grp.GetPostClipNodeGraph().SetLUT(1, dctl)` and every member inherits it (the group API hangs off `project`; `MediaPool` has zero group methods). Four levels: Clip · Group Pre-Clip (before each clip's grade) · **Group Post-Clip (the shared look)** · Timeline (everything, graphics tracks included) — **a group covers only its members, so overlays on V2 stay ungraded**; covering them is the Timeline graph and a decision to confirm, never assume. `Graph` has no AddNode, so the whole look goes in ONE node = a DCTL (escape hatches: `ApplyGradeFromDRX` carries a whole tree; Fusion DOES expose node creation). **Write DCTLs in Blackmagic's own sample dialect** (`/Library/.../Developer/DaVinciCTL/`, `README.txt` = authoritative function list): `const float` locals inside `transform`, `_saturatef`, `_hypotf`, implicit int→float, no early returns, no scientific notation, every literal `f`-suffixed. Deviating cost two failed compiles and **which construct Resolve rejected is still UNKNOWN** (all were on the supported list; clang parsed them clean) — the error is a bare modal with **no diagnostic anywhere, not even `ResolveDebug.txt`**, and `dctl validate` is a stub that returns valid for code Resolve rejects. **The staging trap: `dctl install` writes the USER LUT dir, `set_lut` stages a COPY into the master dir under `MCP/`, and re-installing does NOT re-stage** — Resolve keeps compiling the old file while every readback reports the new name and the render comes back silently ungraded; re-run `set_lut` after each edit, `diff` the two paths, version the filename. Method: measure frames (mean/shadow/highlight/face/median-luma) → design in numpy (~1s/iteration vs ~1min/render; it predicted the render within .01 per channel) → port → **verify with a real render**, never a readback ([`graph get_lut` lies](../../lanes/resolve/resolve-grading/README.md)) and never `get_thumbnail_image` (returns the clip's frame, not the program composite). **Probing leaves grades behind** — testing `SetLUT` across pre-clip/post-clip/item levels left broken LUTs on all three, invisible because a failed DCTL passes through; sweep every level on teardown.
- **Resolve step-3 audio polish = [`lanes/resolve/resolve-audio-polish/`](../../lanes/resolve/resolve-audio-polish/README.md), validated 2026-08-06** (`your-job`: 9 sections, 210 clips, section spread 4.7 → 1.1 LU, zero clips moved). The API has no audio-gain surface, so the pass is ffmpeg on each SOURCE FILE (gated `ebur128` measure per file → static gain to −16 LUFS → −1 dBFS `alimiter` with the house `level=disabled:latency=1` locks → aac 320k into `audio-normalized/`) then `MediaPoolItem.ReplaceClip` under the locked timeline via `replace-clips.py` (before/after track snapshot + REVERT.json). Traps the README carries: verify ZERO timing drift before committing; ReplaceClip RENAMES the pool item (name-keyed scripts break, strip `-vN` when matching) and CLEARS clip color labels; retimed clips keep their ORIGINAL level, with protected ranges derived from AUDIO items, not video. Run immediately after the replay verifies (pipeline step 3, you, 2026-08-28); never per-section during the cut.
- **Resolve delivery render = [`lanes/resolve/resolve-export.md`](../../lanes/resolve/resolve-export.md), measured 2026-08-06.** `VideoQuality` is a dropdown INDEX, not a bitrate (50000 is silently ignored; 100 gives 1.1 Mbps); `MultiPassEncode` is the only real quality lever (18.8 → 36.8 Mbps measured); a multi-pass render looks FROZEN at a tiny file size while working fine; `GetRenderSettings` is not callable, so verify with ffprobe on the finished file. The Premiere CBR-50 lock does NOT port to Resolve; chasing that number already cost one wasted render.
- **Resolve lane wired 2026-08-03:** `davinci-resolve` MCP in `.mcp.json` (machine-local, same pattern as premiere-pro) → pinned gitignored clone at `vendor/davinci-resolve-mcp/` (`samuelgursky/davinci-resolve-mcp` v2.72.0, commit `a9fd831`, update checks set to never — bump the pin deliberately). Compound server (`src/server.py`, 34 grouped tools; `--full` = 341 granular), venv built by `python3 install.py --clients manual`. Talks to the OFFICIAL Resolve scripting API — needs Resolve Preferences → System → General → External scripting = Local (Resolve's shipped default) and the three env vars in `.mcp.json` (`RESOLVE_SCRIPT_API`/`RESOLVE_SCRIPT_LIB`/`PYTHONPATH`). Smoke-tested live over stdio against Resolve Studio 21.0.3.7: initialize, tools/list, `resolve_control get_version`/`get_page`, `project_manager get_current` all pass. No bridge panel needed (unlike Premiere) — the API is in-process via `fusionscript.so`, but Resolve must be RUNNING; `resolve_control launch` can start it (headless supported). **EDL replay validated 2026-08-03 (your-job intro):** one call does the whole rebuild — `media_pool.create_timeline_from_clips` with `clip_infos` `{clip_id, start_frame, end_frame, record_frame}` in SOURCE frames at the raw's fps; `end_frame` is EXCLUSIVE (dur = end − start, matched the EDL 8/8 to the frame), `record_frame` is timeline-relative, linked audio comes along automatically. Set project fps + resolution BEFORE creating the timeline (it inherits). Verify with `timeline.get_items_in_track` readback (starts sit on the 108000 = 01:00:00:00 offset), then `project_manager save` immediately — GUI mode + unsaved project = a modal no script can dismiss. **MATCH THE PROJECT TO THE SOURCE FPS, AND BUILD IT FROM A TEMPLATE — never `create_project` + `set_setting` (2026-08-03 chopped-audio hunt; 2026-08-04 solved).** Step zero of every Resolve job is `ffprobe` on the raw: the project must match the footage (24 fps source → 24 fps project, 30 → 30), never a guess or the last job's value. **ffprobe is only the first read; after import, `GetClipProperty('FPS')` is the authority (iPhone VFR trap, 2026-08-13, Resolve Studio 21.0.4.5).** iPhone `.MOV` is variable frame rate: ffprobe's `r_frame_rate` says `30000/1001` while Resolve ingests the clip at 30.00 native (readback: 20218 frames over 673.92 s = 30.000 exactly), so a 29.97-based template + EDL conversion conformed every clip ÷1.001 and placed every cut ~0.5 s early. Diagnostic: a uniform ÷1.001 (or ×1.001) pattern across every item's duration/left-offset readback means the fps model is wrong; rebuild the project at the right rate (iPhone footage gets 1080p30.drp, not 1080p2997.drp), never nudge frames. The ffmpeg/flat-render path is unaffected (ffmpeg trims by time). A new project defaults to **4K / 24 fps**, and `timelinePlaybackFrameRate` is a **separate setting from `timelineFrameRate` that the API cannot write** — `set_setting` returns `success: false` for every value/type, on a fresh project and on one with a timeline (independently confirmed by `resolve_control api_truth`). A 30 fps timeline left at 24 playback = chopped/glitchy audio. **The fix is `pm.ImportProject()` of a template `.drp`,** which restores fps + resolution wholesale and bypasses `set_setting` entirely — verified by importing the 30 fps template while a 24 fps/4K project was loaded and getting 30/30/1920, so the settings ride in the file rather than leaking from what's open. Templates live in [`lanes/resolve/resolve-templates/`](../../lanes/resolve/resolve-templates/) (+ README on minting new ones); import, strip the inherited timelines/clips, then build. **One template per frame rate** — a template can't be re-pitched (`timelineFrameRate` also goes read-only once a timeline exists); 24 fps is the sole exception, since a stock create is already 24/24. **Minting a new-rate template is scripted, no UI click (2026-08-04):** `lanes/resolve/resolve-templates/mint-template.py` patches the settings blob (keyed-dict → zstd → protobuf; f248 float32 IS the "unwritable" playback rate) — 1080p2997.drp minted and verified this way. Always read both keys back before building. **Never solve this by driving the UI** — UI automation is banned here; the API path is the required route (2026-08-04). Note `probe_project_settings try_write` writes the SAME value back and reports `write: false` even for writable keys — that result is a no-op artifact, not proof a key is read-only. `safe_project_create` needs `allow_non_mcp_name: true` for real (non-`_mcp_`-prefixed) project names. **Keyboard = the stock Adobe Premiere Pro keymap preset.** Resolve ships official Premiere/FCP/Avid/Pro Tools keymaps and was ALREADY on the Adobe Premiere Pro one — never hand-transfer the factory Premiere map. Only personal key overrides need porting (left-hand cluster: A/S edits, E/R frames, V blade, Delete ripple-delete, Z zoom, X/C nudge, L link). Presets export/import as **plain editable text** (`command := Key`, `A | B` for alternates, empty = unbind; on macOS `Ctrl`=Command, `Alt`=Option, `Meta`=Control) — scripted from the exported preset text, never hand-clicked. Export Preset fires a TCC prompt only you can dismiss; the per-key badge on the virtual keyboard lies (imported single bindings show no badge) so verify functionally, not visually. **UI layout = the "Premiere" layout preset (2026-08-03): Media Pool top-left, Effects Library bottom-left, Inspector right (= Effect Controls), tall audio waveforms.** The scripting API's ENTIRE UI surface is page switching + `layout_presets` save/load/export/import — panel toggles, viewer mode, and timeline view options are NOT exposed by Blackmagic, so arranging a layout is a one-time UI job. Unlike the keyboard preset, the layout export is an opaque 88 KB hex blob of serialized Qt widget state — not authorable, only captured. So: arrange once by hand → `layout_presets save` → it's one MCP call to restore forever.
